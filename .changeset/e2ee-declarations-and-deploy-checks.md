An app's files can now declare which columns are end-to-end encrypted. A table's `encryption` entry in `jazz.app.json` names its space (the column holding the space row's ID, or `id` for a table whose rows are their own spaces), its space table (`scope`) and its encrypted columns, and each `history` version carries its own. A schema that declares encryption gains Jazz's system tables for spaces, members, device requests, device keys and account identities and roots, and Jazz derives their permissions itself: an app can't write policies for them, and its own policies may only test the members table with `exists`. The deploy checks the declarations and refuses what could lose or expose data: a space table whose read rule doesn't come from the members table, system tables that don't match the declarations, and a migration that changes an encrypted column's type, space table or space column without a conversion, judged against the declarations each version was first deployed with. It also warns about a space table's update rule that is broader than it looks, and about an encrypted table that is readable more or less widely than its space row. Decrypting a column puts its plaintext on the server and every replica, so the deploy asks you to name it: pass `confirmDecrypt: ["notes.body"]` (a list of `table.column`) to `createJazz` or `deploy`, or set `confirm_decrypt` on the Rust backend, and remove it again once the deployment is out. A server running without a store keeps no declarations, so it asks for the decrypt confirmation on every deploy. An encrypted column may declare a plaintext default (public, since the server stores it), which a migration adding a required encrypted column must give; a conversion can't write over a column that is already encrypted; equality added to existing data starts in `backfill`, can't be dropped while its token column stays, and is allowed on the types the equality format encodes: scalars, enums, JSON (matched by its exact text) and arrays of them. Until encryption ships in clients, every client open (`createJazz`'s backend session, `Jazz::open`, the FFI and the bindings) refuses an app whose files declare it.
