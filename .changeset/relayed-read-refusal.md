A remote query in a browser tab (or any foreground over a worker or native relay) no longer hangs when its relay refuses the server, for example after the server's store was recreated (`authority_changed`), when the relay cannot mirror the server's catalogue, or when the relay's store holds writes made before it ever synced. The tab's `tier: "remote"` subscriptions now fail with the relay's refusal. In Node and the browser, a subscription the core rejects keeps the core error `code`: a changed authority fails with an `AuthorityChangedError` (detect it with `isAuthorityChangedError`), for subscriptions held directly as well as relayed ones. On React Native the refusal's code does not reach JavaScript yet (#5268): a refused remote subscription fails with a plain error, and the link stops with the refusal's reason as before. Local-first queries are not failed: they keep reading the worker's store, as when there is no server. A failed remote subscription stays failed: after `db.reconnect()` (or a store reset), open your `tier: "remote"` subscriptions again, for example by remounting the components that hold them. A `tier: "remote"` one-shot read on a refused link now fails with the refusal at once instead of waiting out its coverage budget.
