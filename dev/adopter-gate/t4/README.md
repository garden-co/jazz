# t4: Next.js + Better Auth on `vercel()`, release-candidate gate

An adopter-style regression check for a Jazz release. A Next.js 16 app with Better Auth (tables in Jazz), guests on device accounts, a claims policy (`team = session.claims.team`) and owner-only rows. It runs on `vercel()` with the thin client, and is deployed to one long-lived Vercel eval project whose core and data carry over between releases.

## Layout

- `app64/`: the app as built on published `2.0.0-alpha.64` (schema DSL, `permissions.ts`, one real migration).
- `app67/`: the same app after `npx jazz-tools@2.0.0-alpha.67 upgrade` (files as source), on published `2.0.0-alpha.67`. `vercel()` still has no `region`, on purpose. This is the default starting point.
- `app*/smoke/smoke.mjs`: the smoke test against the deployed URL (see `app67/smoke/README.md`).
- `scripts/`:
  - `run-t4.sh <version> [app67]`: the whole run. It prints PASS/FAIL/FINDING lines and exits 1 if a required step failed.
  - `rc-deps.sh <app> <version>`: downloads the 4 npm tarballs and checks them against `NPM-SHA256SUMS`. Runs the shipped `newerVersion` cases (`check-newer.mjs`). Sets `package.json` and pnpm `overrides`, installs, then checks that every jazz entry in the lockfile is on `<version>`.
  - `no-region-check.sh <app> [port]`: with `vercel()` lacking `region`, `next build` must fail. The script then runs `next dev` and requires `/jazz` to throw the missing-region error, naming `vercel({ namespace, region: "iad1" })` and the Sandbox regions page.
  - `set-region.sh <app> [region]`: adds `region` to the `vercel({ … })` call.
  - `build.sh <app>`: `jazz-tools generate --check` (or `validate --check` before .66), then `next build`, then sizes (`sizes.py`: first-load JS per route and the shipped wasm, raw and gzip).
  - `deploy.sh <app>`: `vercel deploy --prod` to the eval project.
  - `core-state.sh`: reads the version the production core runs, from the Sandbox's `/tmp/jazz.version`, the Drive's `/data/version` and `/data/bin`, plus its `/health`. Also lists the project's Sandboxes and Drives. Run it after something has woken the core (the smoke test does).
  - `wrong-region-probe.mjs <app> <wrong-region>`: calls the installed release's own `openVercelCore` against the real production core with a wrong region. The real `@vercel/sandbox` is used only for `Sandbox.get({ resume: false })` and for reading `region`/`status`. Every call that could create, resume, start, write or extend anything (`Drive.getOrCreate`, `Sandbox.create`, resume, `runCommand`, `writeFiles`, `extendTimeout`, `stop`, …) is replaced by a stub that throws and is logged. `FAIL_GET_AT=n` makes the n-th `Sandbox.get` throw a transient 503 once. `FAIL_GET_AT=2` exercises the fall-through to `Drive.getOrCreate` found in alpha.68 rc.1 (see jazz#5615).

Not read by the runner, but set on the Vercel project itself (Production environment): `BETTER_AUTH_SECRET` (secret) and `BETTER_AUTH_URL` (the production URL). The local `next build` uses a throwaway `BETTER_AUTH_SECRET`.

Playwright needs no secrets. `npx playwright install --with-deps chromium` needs apt on the runner (sudo on GitHub-hosted runners is fine). Fresh smoke users get a random password for each run and use `@example.com` addresses.

## Rules for the eval project

- Deploy only to the eval project.
- Use synthetic data only.
- Delete nothing: the core and its Drive carry the data that later releases are checked against.
- `region` must stay the core's actual region (`iad1`).
- Serialise runs: one core, one production deployment.

## Preview mode (dry-run RCs)

`T4_MODE=preview` (workflow input `t4_mode: preview`) runs the same steps against a Vercel **preview** of the app instead of production. It builds without `--prod` and runs `deploy --prebuilt`, with a per-run `BETTER_AUTH_SECRET`, since the project's auth vars are production-only. The app's preview core is namespace `cli-previews`. The long-lived production core and the production deployment are never touched. That preview core is shared by dry runs and isn't deleted, because deleting eval resources needs Anselm's word. Previews sit behind Vercel Authentication, so the smoke and `core-state.sh` send `T4_VERCEL_BYPASS_SECRET` (the project's _Protection Bypass for Automation_) as `x-vercel-protection-bypass`. Without it, preview mode reports SKIP.
