# Trusted SQLite catalogue capture v2

A host may retain app metadata learned from an authenticated authority and restore it into another account root for that same registry, application and environment. It must bind those three coordinates outside the opaque native capture. The capture is not a signature and does not authenticate arbitrary caller input.

The native prefix is `JAZZ-SQLITE-CATALOGUE-CAPTURE\0\x02`, followed by postcard fields in this order: namespace option; structural versions and their complete stored table/column names; lens cells; confirmed version/name-digest pairs. Version descriptors use the current `SchemaVersion` codec, which retains public-schema JSON. Versions keep admission order so lens sources can precede targets. Namespace, descriptor identities, names, shape and confirmations are validated before installation. Duplicate, missing, conflicting, trailing, legacy and noncanonical data refuse. The independent empty-catalogue byte fixture pins the entire envelope, including UUID, JSON, vector and option encodings.

Restore is an explicit trusted-host operation during physical owner opening, after normal identity/proof validation and before `Binding::new` starts replica state, sharing, transport or transactions. The `WithCatalogue` constructors provide this boundary while preserving existing constructors and configuration bytes. It refuses schema views, active publications, retired/closed owners and authorities. It preserves the actual owner, identity, selected governing policy and ordinary transaction machinery. It atomically mirrors metadata through current names/type checks; a stale cache does not remove newer durable versions. This adds no storage-format-2 migration or old-writer exclusion protocol. Its requested-schema fence applies to cache-aware runtimes, including queries prepared earlier; it is not an anti-downgrade claim about arbitrary older file writers.

A capture has no application rows, complete history, fresh read cut, accepted evidence, permissions revision, membership or Global receipt. `ready` means only that this handle's requested structural schema has authority-confirmed names. Fresh `coverCatalogue` and accepted-read APIs retain their own authority/session/lifetime checks. Caller-selected policies are never installed from a capture.

`takeAuthenticatedCatalogueState` moves the pending capture once across the shared owner. A host must retain failed publications and durably publish the bytes before advertising cached readiness. Installing cached bytes does not echo them as new online metadata; a newer durable root may export its union again.

The SDK host envelope separately binds the exact registry/application/environment key. Browser publication uses one strict IndexedDB transaction. Node publication serializes validation and replacement with the existing kernel-backed file lock, syncs the file, atomically renames it and syncs the directory. Ephemeral caches explicitly promise only one host lifetime. No cache changes current authority validation, pending proof, rejection or original transaction fate.

Host operations snapshot registry/application/environment before awaiting storage; publication also copies capture bytes before validation or I/O. Replacement validation and durable publication therefore use the same bytes and scope even if a caller changes its original inputs. Opening a transaction still admits a live handle: actual reads and writes independently refuse a requested schema missing from the restored catalogue.
