- `app` and `permissions` are the ones your code imports. The bundle that's running is the bundle
  Jazz enforces, so rolling back your backend rolls back its permissions too.
- `authenticate(request)` reads your own session (a cookie, a header) and returns
  `{ userId, claims? }`, or `null` when signed out. It is the only place that decides who a user
  is: sign-ins, sync connections and `forReqUser` all ask it. There's no Jazz token in the browser.
  If your provider issues JWTs, [`fromJWT()`](/docs/setup/auth/custom#tokens-from-your-identity-provider)
  is a ready-made `authenticate`. See [How Auth Works in Jazz](/docs/setup/auth/backend).
- Admin and backend routes never leave the process: from outside, only sync and sign-in are
  reachable under `/jazz`.
- `createJazz` opens nothing when your module loads: the store opens on first use, such as the first
  request or `jazz.db` call, and there's one Jazz per store per process. So it's safe at a module's
  top level everywhere, including Next.js, whose build and dev workers import your modules too.
  `await jazz.ready()` opens it right away, for a server that should fail at startup rather than on
  its first request.
