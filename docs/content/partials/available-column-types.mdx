There are a number of column types available which cover most common use cases. In
`jazz.app.json`, a column is a type string, or an object when it has options:

| `jazz.app.json`                 | TypeScript type           | SQL type        |
| ------------------------------- | ------------------------- | --------------- |
| `"string"`                      | `string`                  | `TEXT`          |
| `"boolean"`                     | `boolean`                 | `BOOLEAN`       |
| `"int"`                         | `number`                  | `INTEGER`       |
| `"bigint"`                      | `bigint`                  | `BIGINT`        |
| `"float"`                       | `number`                  | `REAL`          |
| `"timestamp"`                   | `Date`                    | `TIMESTAMP`     |
| `"bytes"`                       | `Uint8Array`              | `BYTEA`         |
| `"uuid"`                        | `string` (row ID)         | `UUID`          |
| `{ "array": "string" }`         | `string[]`                | `TEXT[]`        |
| `{ "enum": ["a", "b"] }`        | `"a" \| "b"`              | `ENUM('a','b')` |
| `{ "json": true }`              | `JsonValue`               | `JSON`          |
| `{ "json": { …JSON Schema… } }` | generated from the schema | `JSON`          |

Any column can be made nullable with a trailing `?` (`"string?"`), or `"optional": true` in the
object form. The object form takes `"type"` for a plain type and options next to it:
`{ "type": "int", "default": 0 }`, `{ "type": "string", "merge": "text" }`,
`{ "array": "uuid", "optional": true }`.

`int` values are signed 32-bit integers from `-2,147,483,648` through `2,147,483,647`. The
runtime rejects fractional, non-finite, and out-of-range values before sending a write to the
native engine. Use `float` when a wider or fractional numeric range is required.

An enum's cases can carry data:
`{ "enum": { "pending": {}, "approved": { "by": "uuid", "note": "string?" } } }` is the TypeScript
type `{ type: "pending" } | { type: "approved"; by: string; note: string | null }`.

> **JSON columns are atomic.** The entire value is replaced on every write. Use `{ "json": true }` for untyped JSON, or `{ "json": <JSON Schema> }` to validate values and get a TypeScript type for them. The generated type covers `type`, `properties`/`required`, `items`, `enum`, `const`, `anyOf`/`oneOf` and `nullable`; other keywords give `unknown`. For structured data that needs per-field updates, use separate columns or a related table instead.

> Declare relations separately from columns, under the table's `relations`: `{ "rel": "targetTable", "column": "localUuidColumn" }` and `{ "reverse": "sourceTable", "relation": "forwardRelationName" }`. UUID columns have no naming convention.

JSON pointer selections require a JSON column. Text columns containing JSON text are not JSON columns. JSON is validated when written; pointer reads can therefore skip unrelated chunks in a large value. Array indices must be canonical (`0`, `1`, …); `/01` does not select array index 1, but can select an object property named `"01"`.
