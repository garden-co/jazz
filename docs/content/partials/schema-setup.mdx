Check your app files and regenerate the bindings:

`npx jazz-tools generate`

This checks `jazz.app.json` and `jazz.permissions.json` with the same loader your backend runs,
then writes `jazz.generated.ts`. Errors name the file, the JSON path and, inside an expression, the
exact spot, with a suggestion. In CI, `npx jazz-tools generate --check` writes nothing and fails
when `jazz.generated.ts` is missing or out of date.

When you change `tables` after the bindings were generated, `generate` refuses until the change has
a migration:

```text
the schema changed since the last version: run `jazz-tools migrations create --name <name>`
```

Run it as it says, review the migration it writes into `jazz.app.json`, and see
[Migrations](/docs/schemas/migrations). Then restart your main backend (locally) or deploy it as
usual: on start, `createJazz` publishes the new schema, permissions and migrations.
