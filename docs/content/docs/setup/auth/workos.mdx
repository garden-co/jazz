[WorkOS](https://workos.com/) AuthKit hosts the sign-in pages. Run its server-side flow in the
backend that hosts Jazz: the callback stores a sealed session cookie, and `authenticate` loads it.

```ts title="server.ts"
import { WorkOS } from "@workos-inc/node";
import { createJazz, remote } from "jazz-tools/backend";

export const workos = new WorkOS(process.env.WORKOS_API_KEY, {
  clientId: WORKOS_CLIENT_ID,
});
export const cookiePassword = process.env.WORKOS_COOKIE_PASSWORD!;

// GET /auth/callback: exchange the code and set the `wos_session` cookie.
const { sealedSession } = await workos.userManagement.authenticateWithCode({
  code,
  clientId: WORKOS_CLIENT_ID,
  session: { sealSession: true, cookiePassword },
});

// The session's access token lasts minutes. When it has expired, refresh once and
// remember the new seal for the stale one: refresh tokens are single-use, so concurrent
// requests and sync sockets (which can't set a cookie) must all use the same new seal.
// Your HTTP responses write `session.sealed` as the cookie when it changed.
const refreshed = new Map<string, Promise<string | null>>();
export async function readSession(sealed: string) {
  const current = (await refreshed.get(sealed)) ?? sealed;
  const session = workos.userManagement.loadSealedSession({ sessionData: current, cookiePassword });
  const auth = await session.authenticate();
  if (auth.authenticated) return { ...auth, sealed: current };
  if (!refreshed.has(sealed)) {
    refreshed.set(
      sealed,
      session.refresh().then((next) => (next.authenticated && next.sealedSession) || null),
    );
    // Long enough for the requests racing on this stale seal; then forget it.
    setTimeout(() => refreshed.delete(sealed), 5 * 60_000);
  }
  const fresh = await refreshed.get(sealed);
  if (!fresh) return null;
  const again = await workos.userManagement
    .loadSealedSession({ sessionData: fresh, cookiePassword })
    .authenticate();
  return again.authenticated ? { ...again, sealed: fresh } : null;
}

export const jazz = createJazz({
  app,
  permissions,
  store: remote({ appId, url, secret }),
  authenticate: async (request) => {
    const sessionData = readCookie(request, "wos_session");
    const session = sessionData ? await readSession(sessionData) : null;
    if (!session) return null;
    return {
      userId: session.user.id,
      claims: { role: session.role ?? "" },
      // The sealed session doesn't say when it ends, so authenticate again in an hour, not at
      // the access token's `exp`: Jazz's routes skip your auth middleware, so that token isn't
      // refreshed there, and the connection would reconnect every few minutes for nothing.
      expiresAt: Math.floor(Date.now() / 1000) + 60 * 60,
    };
  },
});
```

Write the new seal as the `wos_session` cookie on your HTTP responses, for example in middleware on
your app's own routes, so the browser's next request carries it. The
[WorkOS chat example](https://github.com/garden-co/jazz/tree/main/examples/auth-workos-chat) does
this.

An hour is also the longest a sync connection lasts by default (`sessionTtlSeconds`). A session
revoked at WorkOS (a sign-out on another device, or by an admin) is caught when its access token
has expired and the refresh fails: `readSession` returns `null`, and Jazz signs the user out. Until
then, and at most for that hour, an open connection on another device stays live. A sign-out in
this browser reaches its other tabs at once through the client, as below (see
[When a session expires](/docs/setup/auth/backend#when-a-session-expires)).

If your backend receives WorkOS access tokens instead (for example, from a native app sending
`Authorization: Bearer`), use `fromJWT`. Their `role`, `permissions` and `org_id` claims reach your
policies as `session.claims`:

```ts
authenticate: fromJWT({
  jwksUrl: `https://api.workos.com/sso/jwks/${WORKOS_CLIENT_ID}`,
  issuer: `https://api.workos.com/user_management/${WORKOS_CLIENT_ID}`,
  // WorkOS access tokens carry no `aud`; the issuer already names your client id.
  audience: false,
}),
```

## Signing out

AuthKit's `signOut()` redirects, so the tab leaves before Jazz hears of it, and the browser's other
tabs stay signed in until they're in front again. Sign out without redirecting instead: end the
session and clear its cookie in a server action, then call `refresh()` on the client and navigate,
as in [Signing out in every tab](/docs/setup/auth/backend#signing-out-in-every-tab):

```ts title="actions.ts"
"use server";
import { cookies } from "next/headers";
import { readSession, workos } from "./server";

export async function signOutAction() {
  const store = await cookies();
  const sessionData = store.get("wos_session")?.value;
  // readSession refreshes an expired access token, so the session id is there even then.
  const session = sessionData ? await readSession(sessionData) : null;
  // End the session at WorkOS too, so its refresh token stops working on every device.
  if (session) await workos.userManagement.revokeSession({ sessionId: session.sessionId });
  store.delete("wos_session");
}
```

If the session has already ended at WorkOS, there is nothing to revoke, and deleting the cookie
signs this browser out.
