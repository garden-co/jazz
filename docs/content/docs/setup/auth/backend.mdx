---
title: Your Backend Decides
description: "With createJazz, your backend's authenticate function is the only place that decides who a user is. The browser needs no Jazz API key or token."
---

When Jazz runs inside your backend ([Backend](/docs/setup/backend)), auth is one function. Your
backend already knows who is signed in, so it tells Jazz:

```ts title="jazz.server.ts"
import { createJazz, sqlite } from "jazz-tools/backend";
import { auth } from "./auth"; // your Better Auth instance
import { app, permissions } from "./schema";

export const jazz = await createJazz({
  app,
  permissions,
  store: sqlite({ path: "./data/jazz" }),
  authenticate: async (request) => {
    const session = await auth.api.getSession({ headers: request.headers });
    return session ? { userId: session.user.id, claims: { role: session.user.role } } : null;
  },
});
```

- `userId` is your user's stable id. Jazz gives each one an account the first time they sign in.
- `claims` are anything your [policies](/docs/schemas/policies) should see, under `session.claims`.
- Return `null` for a signed-out request.

Jazz asks `authenticate` on every sign-in, on every sync connection and in `jazz.forRequest`. A
sign-out or changed claims apply on the next reconnect, and a connection ends when its sign-in
expires (after an hour by default, `sessionTtlSeconds`), so the client reconnects and is asked
again. There are no JWKS, issuer or audience settings, and no Jazz token in the browser.

## In the browser

```tsx title="App.tsx"
import { JazzProvider } from "jazz-tools/react";
import { authClient } from "./auth-client";

function Root() {
  const { data, isPending } = authClient.useSession();
  return (
    // undefined while your auth loads, null when signed out, the user's id when signed in
    <JazzProvider user={isPending ? undefined : (data?.user.id ?? null)} signedOut={<SignIn />}>
      <App />
    </JazzProvider>
  );
}
```

`user` is whatever your auth library already says about the current user: `undefined` while it's
loading, `null` when signed out, and a stable id when signed in. When it changes, Jazz signs in again
through your backend; the identity itself always comes from `authenticate`, never from the prop.
That's the whole integration, and it works the same with Better Auth, Clerk, Auth.js, Supabase or
your own sign-in:

- **Sign-out.** When `user` becomes `null`, Jazz closes the account's client. A local-first client's
  unsynced writes stay in that account's local storage and sync the next time the same user signs
  in. On shared devices, pass `clearOnSignOut` to wipe them instead.
- **Sign-out elsewhere.** Another tab, an expired session or a revoked one: your backend re-runs
  `authenticate` on open connections, and when it returns `null` Jazz ends the connection as
  signed out. No client code needed.
- **Without the prop**, Jazz asks your backend on start, when the tab regains focus and when another
  tab signs in or out. The prop only makes changes instant.

Without a framework, pass the same value from your auth library's own listener:

```ts
import { createClient } from "jazz-tools/thin";

const db = await createClient();
supabase.auth.onAuthStateChange((_event, session) => db.setUser(session?.user.id ?? null));
```

## Several sign-in methods

Email, Google, passkeys and the rest belong to your auth library, which already merges them into one
user. As long as `authenticate` returns that user's id, Jazz sees the same account whichever method
was used.

## Upgrading a guest, linking identities

A local-first guest who signs up keeps its account and data: after your sign-up sets its session,
the client calls `linkWithBackend()`. It proves it owns the guest account with its own local-first
key; your backend runs `authenticate` and links the new user to that account. Call it in your sign-up
handler, right after your auth sets the session; the `user` change that follows is then a no-op.

To link from your own backend code instead, for example a second identity your auth issued, call:

```ts title="app/api/sign-up/route.ts"
await jazz.linkIdentity({ from: guestId, to: user.id });
```

From then on, `authenticate` returning `user.id` opens the guest's account and all its data. An
identity can belong to only one account, so `to` must not have signed in to Jazz on its own yet.
