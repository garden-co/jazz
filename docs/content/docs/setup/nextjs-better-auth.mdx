This page puts the default stack together in order: a Next.js app with Jazz in its own backend,
Better Auth for sign-in with its tables in Jazz, the thin client in the browser, deployed to
Vercel. The code comes from the
[Better Auth chat example](https://github.com/garden-co/jazz/tree/main/examples/auth-betterauth-chat),
which is tested end to end. Each step links to the page with the details.

## 1. Install

<include>../../partials/install-alpha.mdx</include>

```bash title="Terminal"
npm install better-auth ws @vercel/functions @vercel/sandbox
```

`ws` and `@vercel/functions` let sync use a WebSocket on Vercel, and `@vercel/sandbox` runs the
`vercel()` store. Keep Jazz's native module out of Next's server bundle:

```ts title="next.config.ts"
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  serverExternalPackages: ["jazz-napi"],
};

export default nextConfig;
```

## 3. Permissions

Policies decide who may read and write each row. Merge your own with the generated
`permissions`, which keep browsers away from Better Auth's tables:

<include cwd lang="ts" meta='title="permissions.ts"'>
  ../examples/auth-betterauth-chat/permissions.ts#default-stack-permissions
</include>

Here anyone signed in reads both rooms and writes in the general one, only admins post
announcements, and people change only their own messages; the role comes from the claims
`authenticate` returns. See [Declarative Permissions](/docs/schemas/policies).

## 4. Jazz and Better Auth in your backend

`createJazz` runs Jazz inside your Next.js app, and Better Auth keeps its users and sessions in it
through the Jazz adapter. `authenticate` asks Better Auth who a request's session cookie belongs
to:

```ts title="jazz.server.ts"
import { betterAuth } from "better-auth";
import { nextCookies } from "better-auth/next-js";
import { admin } from "better-auth/plugins";
import { createJazz, perBranch, vercel } from "jazz-tools/backend";
import { jazzAdapter } from "jazz-tools/better-auth-adapter";
import { app } from "./schema";
import permissions from "./jazz.permissions.json" with { type: "json" };

export const jazz = createJazz({
  app,
  permissions,
  // Production gets one core, and each preview branch its own (on your own server: sqlite()).
  store: vercel({
    namespace: ({ environment, branch }) =>
      environment === "production" ? "production" : perBranch(branch),
  }),
  authenticate: async (request) => {
    const session = await auth.api.getSession({ headers: request.headers });
    if (!session) return null;
    const role = (session.user as { role?: string | null }).role;
    return {
      userId: session.user.id,
      expiresAt: Math.floor(session.session.expiresAt.getTime() / 1000),
      claims: { role: role ?? "member" }, // from the admin plugin below
    };
  },
});

export const auth = betterAuth({
  database: jazzAdapter({ db: async () => jazz.db, schema: app.wasmSchema }),
  emailAndPassword: { enabled: true },
  plugins: [admin({ adminRoles: ["admin"], defaultRole: "member" }), nextCookies()],
});
```

The role comes from Better Auth's admin plugin; leave out the plugin and `claims` if your policies
don't use roles. See [Better Auth](/docs/setup/auth/better-auth) and
[How Auth Works](/docs/setup/auth/backend).

Mount Jazz under `/jazz`, where the browser connects by default, next to Better Auth's own route:

```ts title="app/jazz/[...path]/route.ts"
import { jazz } from "@/jazz.server";

export const { GET, POST, DELETE } = jazz.next();
```

```ts title="app/api/auth/[...all]/route.ts"
import { toNextJsHandler } from "better-auth/next-js";
import { auth } from "@/jazz.server";

export const { GET, POST } = toNextJsHandler(auth);
```

Keep auth middleware off `/jazz/` (see
[Keep auth middleware off Jazz's routes](/docs/setup/auth/backend#keep-auth-middleware-off-jazzs-routes)).

## 5. The browser

`<JazzProvider>` opens the thin client: no Wasm, no local storage, and every query and write goes
to your backend under the signed-in user's policies. It's a client component, so render it from a

## 7. Run it locally

```bash title="Terminal"
npx jazz-tools validate
npm run dev
```

Under `next dev`, `vercel()` keeps its data in a SQLite file in `.jazz/local` (add `.jazz/` to
`.gitignore`), and the browser syncs over an HTTP stream; nothing else to set up. See [Vercel](/docs/setup/deployment/vercel#local-development).

## 8. Deploy to Vercel

Push to Git or run `vercel deploy`. Production gets its own Jazz core and data, and each preview
branch its own, as `namespace` above says; see
[Production, previews and development](/docs/setup/deployment/vercel#production-previews-and-development)
for sharing one preview core instead. Before real users arrive:

- Connect a Vercel Blob store to production (and one per preview environment, if previews store
  files), so large values don't grow the core's database.
- Set `publicUrl` to the URLs your users reach `/jazz` at.
- Set `BETTER_AUTH_SECRET` and Better Auth's base URL for each environment.

See [Vercel](/docs/setup/deployment/vercel) for each of these, and [Testing](/docs/tooling/testing)
to check your policies before you ship.
