## Start with your agent

Paste this into your coding agent, or tell it to run `npm create jazz` and follow the output. Both
give it the same brief, which always lives at
[jazz.tools/quickstart.md](https://jazz.tools/quickstart.md).

## The questions your agent will ask

Each one has a default, so "you pick" is a fine answer.

- **Where will it be deployed?** Vercel or your own server; Cloudflare is coming. Default: Vercel for Next.js, your own server otherwise. See [Vercel](/docs/setup/deployment/vercel) and [Your Own Server](/docs/setup/deployment/own-server).
- **Which auth?** Whatever your backend already uses; Better Auth for a new app. See [How Auth Works](/docs/setup/auth/backend).
- **Which backend framework?** Next.js, Hono, Express / Node, Bun or Effect. Default: Next.js.
- **API routes only, or Jazz from the frontend too?** If the frontend, the thin client (default) or local-first, and React, Vue, Svelte, Solid or plain TypeScript. React Native is always local-first. See [Thin Client](/docs/setup/web-client/thin-client).
- **What is the data, and who may read or write it?** Your agent shows you the schema and policies before building the rest. See [Defining Tables](/docs/schemas/defining-tables) and [Declarative Permissions](/docs/schemas/policies).

## How your agent knows it's done

There's no check command. Your agent shows you each of these working:

- The dev setup starts with one command
- A backend route writes a row that a live query in the UI shows without a reload
- A second user can't read rows the policies say are private, and the permission tests pass (see [Testing](/docs/tooling/testing))

It finishes with the commands to run, what it chose and why, and any docs that were wrong or missing, with their URLs.

## Run it yourself

Install Jazz with `npm install jazz-tools`. That's Jazz 2, in alpha and leaving it soon; versions
before 2.0 are Classic Jazz, with a different API.

Jazz runs inside your backend's dev server, so there's nothing extra to start. Create it once and
mount it under `/jazz`:

```ts title="jazz.server.ts"
import { createJazz, sqlite } from "jazz-tools/backend";
import { app } from "./schema";
import permissions from "./jazz.permissions.json" with { type: "json" };

export const jazz = createJazz({
  app,
  permissions,
  store: sqlite({ path: "./data/jazz" }),
  // Read your session; return { userId, expiresAt, claims? } for a signed-in user, or null
  authenticate: async (request) => null,
});
```

Edit `permissions.ts` and restart the dev server: Jazz applies it on start. Changing `schema.ts`
once the store holds data needs a migration first: run `npx jazz-tools migrations create` before
the first schema change, then again after each one (see [Migrations](/docs/schemas/migrations)). A
store that refuses the app after a schema change is missing a migration; don't delete it. Don't
count on hot reload for either file: Turbopack usually recovers, but webpack builds can get stuck on
the old schema. See
[Your Own Server](/docs/setup/deployment/own-server) for mounting it in Next.js, Hono or Express.

## How we test this page

An "agent as adopter" suite runs this brief end to end: a coding agent in a clean sandbox, a
simulated user answering its questions, and a separate LLM judge checking the done list. For now we
run it by hand as a release gate.
