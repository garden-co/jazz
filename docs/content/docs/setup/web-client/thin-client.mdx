The default browser client: about 160 KB gzipped, with no Wasm and no local storage. Your main
backend runs every query under the signed-in user's policies and sends finished rows, and writes
commit on the server.

## Connect

The thin client is what you get with no choice made: `JazzProvider` in React, or `createJazzClient`
from `jazz-tools/client`, without a `client` loader.

<Tabs groupId="jazz-framework" items={["React", "TypeScript"]} persist updateAnchor>
  <Tab value="React">
    ```tsx title="App.tsx"
    import { JazzProvider } from "jazz-tools/react";

    function Root() {
      return (
        <JazzProvider signedOut={<SignIn />}>
          <App />
        </JazzProvider>
      );
    }
    ```

  </Tab>
  <Tab value="TypeScript">
    ```ts title="app.ts"
    import { createJazzClient } from "jazz-tools/client";
    import { app } from "./schema";

    const jazz = await createJazzClient({});
    // After your own sign-in or sign-out, ask your backend again.
    authClient.onSessionChange(() => void jazz.reauthenticate());
    const db = jazz.getSnapshot().client!.db;

    const todos = await db.all(app.todos);
    ```

  </Tab>
</Tabs>

## Options

<include>../../../partials/web-client-shared-options.mdx</include>

The thin client also takes:

| Option              | Default              | What it does                                                   |
| :------------------ | :------------------- | :------------------------------------------------------------- |
| `reconnectDelaysMs` | a short backoff      | Delays between reconnect attempts, in ms; the last one repeats |
| `WebSocket`         | the global WebSocket | A WebSocket implementation, for runtimes without a global one  |

There is no `driver` option, since the thin client keeps nothing locally.

## What runs on the server

- Transactions (mergeable and serializable), branch and snapshot views (`db.captureSnapshot`, branch/base options), large-value streaming (`insertStreaming` / `upsertStreaming`)

## Limitations

Each is an explicit "not supported" error:

- no offline use: while the backend is unreachable, reads and subscriptions wait and are answered after the reconnect; writes are not optimistic: they show after one round trip, and `wait()` resolves when the server answered
- no attributed writes
- no streaming inside a transaction
- no admin secret in the browser

## Upgrading to local-first

Hand the provider a loader for the local-first client. It starts thin, then upgrades in the
background after the first load. The thin client finishes its writes before it shuts down:

```tsx
<JazzProvider client={() => import("jazz-tools/local-first")}>
```

The dynamic import lives in your code, so the local-first client and its Wasm become a separate
chunk: apps that never pass `client` never download it.

To upgrade only when you need to, for example when a user opens an editor or goes offline, call
the hook instead:

```tsx
const { upgradeToLocalFirst } = useDb();
await upgradeToLocalFirst(() => import("jazz-tools/local-first"));
```

Without a framework, `upgradeToLocalFirst(db, () => import("jazz-tools/local-first"))` from
`jazz-tools/thin` returns the local-first `Db` to use from then on. See
[Local-First Client](/docs/setup/web-client/local-first-client).
