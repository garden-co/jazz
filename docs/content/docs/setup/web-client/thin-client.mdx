The default web client: about 86 KB gzipped, no Wasm, no local storage. The server runs every query under the signed-in session's policies and sends finished rows; writes commit on the server.

## Configure one session

Open one client for the app. It signs in through your [main backend](/docs/setup/deployment) at
`/jazz`, with your app's own session cookie, and returns the same `Db` as the local-first client:
queries, `subscribe`, insert, update, upsert, delete and the framework hooks all work.

<Tabs groupId="jazz-framework" items={["React", "TypeScript"]} persist updateAnchor>
  <Tab value="React">
    ```tsx title="App.tsx"
    import { JazzProvider } from "jazz-tools/react";
    import { authClient } from "./auth-client";

    function Root() {
      const { data, isPending } = authClient.useSession();
      return (
        <JazzProvider
          client="thin"
          // undefined while your auth loads, null when signed out, the user's id when signed in
          user={isPending ? undefined : (data?.user.id ?? null)}
          signedOut={<SignIn />}
        >
          <App />
        </JazzProvider>
      );
    }
    ```

  </Tab>
  <Tab value="TypeScript">
    ```ts title="app.ts"
    import { createClient } from "jazz-tools/thin";
    import { app } from "./schema";

    const db = await createClient();
    // Follow your auth library's current user: null when signed out.
    authClient.onSessionChange((session) => db.setUser(session?.user.id ?? null));

    const todos = await db.all(app.todos);
    ```

  </Tab>
</Tabs>

Who the user is always comes from your backend's `authenticate`; see
[How Auth Works](/docs/setup/auth/backend).

## Client config options

| Option              | Default              | What it does                                                                        |
| :------------------ | :------------------- | :---------------------------------------------------------------------------------- |
| `serverUrl`         | `/jazz`              | Where your main backend mounts Jazz. Set it only if you mount it somewhere else     |
| `user`              | asks your backend    | Your auth library's current user: `undefined` while loading, `null` when signed out |
| `reconnectDelaysMs` | a short backoff      | Delays between reconnect attempts, in ms; the last one repeats                      |
| `WebSocket`         | the global WebSocket | A WebSocket implementation, for runtimes without a global one                       |

There is no `driver` option, since the thin client keeps nothing locally.

## What runs on the server

- Transactions (mergeable and serializable), branch and snapshot views (`db.captureSnapshot`, branch/base options), large-value streaming (`insertStreaming` / `upsertStreaming`)

## Limitations

Each is an explicit "not supported" error:

- no offline use; writes are not optimistic: they show after one round trip, and `wait()` resolves when the server answered
- no attributed writes
- no streaming inside a transaction
- no admin secret in the browser
- not yet: serving thin clients from your own Node backend

## Upgrading to local-first

- `upgradeToLocalFirst(thinDb, () => import("jazz-tools").then((jazz) => jazz.createClient(config)))` loads every subscribed query into a local-first `Db` for the same account, lets the thin `Db` finish its writes, and hands back the new `Db` to swap in. See [Local-First Client](/docs/setup/web-client/local-first-client).
