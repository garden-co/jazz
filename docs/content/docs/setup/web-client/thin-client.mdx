title: Thin Client
description: "A small browser client that talks to your server, with no local database."
---

<Callout type="info">
  Preview: this page is a rough outline for the server-first docs restructure. The thin client is
  still being built; this page describes it once it ships.
</Callout>

- The default web client: about 86 KB gzipped, no WASM, no local storage
- Installation: import from `jazz-tools/thin`
  - `createAccountManager({ appId, serverUrl })`&hairsp;—&hairsp;the same account API as `jazz-tools`
  - `createDb({ appId, serverUrl, account })`&hairsp;—&hairsp;returns the normal `Db`; queries, `subscribe`, insert/update/upsert/delete and the framework hooks all work
- Where it connects: `serverUrl` points at a Jazz server's native endpoint (your self-hosted server or Jazz Cloud). The server runs every query under the signed-in session's policies and sends finished rows; writes commit on the server
- User auth integration
- Runs on the server: transactions (mergeable and serializable), branch and snapshot views (`db.captureSnapshot`, branch/base options), large-value streaming (`insertStreaming` / `upsertStreaming`)
- Limitations, each an explicit "not supported" error:
  - no offline use; writes are not optimistic: they show after one round trip, and `wait()` resolves when the server answered
  - no attributed writes
  - no streaming inside a transaction
  - no admin secret in the browser
- Upgrading lazily to the [local-first client](/docs/recipes/local-first) with `upgradeToLocalFirst(thinDb, () => import("jazz-tools").then((jazz) => jazz.createDb(config)))`: it loads every subscribed query into a local-first `Db` for the same account, lets the thin `Db` finish its writes, and hands back the new `Db` to swap in
- Not yet: serving thin clients from your own Node backend
