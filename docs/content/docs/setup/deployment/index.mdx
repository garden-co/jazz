Jazz runs inside your backend. There is no separate Jazz server to start and no deploy step:
`createJazz` opens the database in your backend's process, applies the schema, migrations and
permissions your code declares, and serves sync on your own origin under `/jazz`.

These docs call that backend your **main backend**. Every browser and app syncs through it, and its
`authenticate` function decides who each user is. Other trusted machines, such as a job runner, a
script or a second service, connect through it as **backend clients** (machine-to-machine access).
See [Backend Client](/docs/setup/backend-client).

## Where the data lives

Each page below is a complete setup for one place your main backend can run, from `createJazz` to
the first query:

- [Vercel](/docs/setup/deployment/vercel): your Next.js app on Vercel, with each environment's data
  in its own Vercel Sandbox (`vercel()` store).
- [Jazz Cloud](/docs/setup/deployment/jazz-cloud): any backend, with the data stored and synced on
  the hosted Jazz Cloud (`remote()` store).
- [Your Own Server](/docs/setup/deployment/own-server): a Node server, VM or container, with the
  data in SQLite on its disk (`sqlite()` store).

`memory()` keeps the data in the process, for tests and throwaway previews. See
[Testing](/docs/tooling/testing).
