Jazz Cloud stores and syncs your app's data. Your own backend sits in front of it: browsers talk only to your backend, which signs users in with your auth and connects to Jazz Cloud. Jazz Cloud does no user auth of its own.

This page sets up your **main backend**: the backend that runs `createJazz`, serves sync to your
browsers and apps, and decides who each user is. Other trusted machines reach Jazz through it as
[backend clients](/docs/setup/backend-client).

## Get an app ID

Your app ID namespaces your data for storage and sync. Click below to generate one on Jazz Cloud. You also get the secrets your backend needs. Generated apps are unclaimed until you claim them in the dashboard, and unclaimed apps are deleted after 14 days.

## Connect your backend

Put the generated values in your backend's environment. All of them stay server-side; the browser never needs the app ID or the sync URL, and the admin secret is like a database password:

```bash title=".env"
JAZZ_APP_ID="<your app ID>"
JAZZ_SERVER_URL="https://v2.sync.jazz.tools/"
JAZZ_ADMIN_SECRET="<admin secret>"
```

Then point `createJazz` at Jazz Cloud with the `remote()` store:

```ts title="jazz.server.ts"
import { createJazz, remote } from "jazz-tools/backend";
import { app, permissions } from "./schema";

export const jazz = await createJazz({
  appId: process.env.JAZZ_APP_ID!,
  app,
  permissions,
  store: remote({
    url: process.env.JAZZ_SERVER_URL!,
    secret: process.env.JAZZ_ADMIN_SECRET!, // the app's admin secret
  }),
  // Who is signed in, read from your own auth's session.
  authenticate: async (request) => {
    const session = await getSession(request);
    return session ? { userId: session.user.id } : null;
  },
});
```

On start, your backend applies its schema, migrations and permissions to the app on Jazz Cloud. For each request it tells Jazz Cloud who the user is, which is why `authenticate` lives in your backend. Browsers sync with your backend under `/jazz`, never with Jazz Cloud directly.
