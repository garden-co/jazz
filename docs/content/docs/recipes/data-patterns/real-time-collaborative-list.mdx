Every client subscribes to the same data and sees changes as they happen. This recipe shows the pattern end-to-end.

## Schema

A shared project with collaboratively-edited tasks.

```ts title="schema.ts"
import { schema as s } from "jazz-tools";

export const schema = s.defineSchema({
  projects: s.table(
    { name: s.string() },
    {
      tasks: s.reverse("tasks", "project"),
      members: s.reverse("projectMembers", "project"),
    },
  ),
  tasks: s.table(
    {
      title: s.string(),
      done: s.boolean(),
      assignee_id: s.uuid().optional(),
      projectId: s.uuid(),
    },
    { project: s.rel("projects", "projectId") },
  ),
  projectMembers: s.table(
    { projectId: s.uuid(), user_id: s.uuid() },
    { project: s.rel("projects", "projectId") },
  ),
});
```

## Permissions

Project members can read and write tasks. The creator can manage membership. Tasks inherit access from their project via `allowedTo`.

```ts title="schema.ts"
const { definePermissions, exists, allowedTo, session, anyOf } = schema;

const createdByMe = { $createdBy: session.user };

export const permissions = definePermissions({
  // The creator and members.
  projects: {
    read: (project) =>
      anyOf(createdByMe, exists.projectMembers({ projectId: project.id, user_id: session.user })),
    insert: true,
    update: createdByMe,
  },
  // Inherit from the project.
  tasks: {
    read: (task) => allowedTo.read(task.project),
    insert: (task) => allowedTo.read(task.project),
    update: (task) => allowedTo.read(task.project),
  },
  // Only the creator can manage members.
  projectMembers: {
    insert: (member) => member.project.where(createdByMe),
    read: (member) => anyOf(member.project.where(createdByMe), { user_id: session.user }),
  },
});
```

See [Declarative Permissions](/docs/schemas/policies) for `exists`, `anyOf` and `allowedTo`.

## Subscribing to shared data

When multiple clients subscribe to the same query, they all see each other's changes in real-time.

When Alice inserts a task it appears in her UI instantly, syncs to the server, and the server pushes it to Bob&hairsp;—&hairsp;whose `useAll` subscription re-renders automatically.

<Accordions type="single">
<Accordion title="How sync and conflicts work">
When two users edit the same row concurrently, Jazz merges per column. Each column resolves independently, so if Alice updates `title` while Bob updates `done`, both changes are preserved. If they both update `title`, [the edit the server receives last wins](/docs/recipes/local-first/how-sync-works#concurrent-edits) and the other is kept in the row's history.

For most applications this is the right default. See [How sync works](/docs/how-jazz-works) for more detail.
