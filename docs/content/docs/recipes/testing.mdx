Use the public schema and `Db` APIs in tests. The testing package provides a local server and
isolated database contexts so tests exercise the same query, policy, and transaction surface as an
application.

## Test a local database

Use a memory driver for a fast isolated database. Await `shutdown()` in cleanup so runtimes and
subscriptions are released.

```ts
import { afterEach, beforeEach, describe, expect, it } from "vitest";
import { createDb, generateAuthSecret, type Db } from "jazz-tools";
import { app } from "../schema.js";

let db: Db;

beforeEach(async () => {
  db = await createDb({
    appId: crypto.randomUUID(),
    secret: generateAuthSecret(),
    driver: { type: "memory" },
  });
});

afterEach(async () => {
  await db.shutdown();
});

it("writes and reads a current row", async () => {
  const todo = db.insert(app.todos, { title: "Write a test" });
  await todo.wait({ tier: "local" });

  await expect(db.one(app.todos.where({ id: todo.value.id }))).resolves.toMatchObject({
    title: "Write a test",
  });
});
```

## Test policy decisions

Use `createPolicyTestApp` to make focused assertions over a compiled schema and a supplied session.
Keep policy tests close to `permissions.ts`; test both allowed and denied operations.

```ts
import { expect } from "vitest";
import { createPolicyTestApp } from "jazz-tools/testing";
import { app } from "../schema.js";
import permissions from "../permissions.js";

const policyApp = await createPolicyTestApp(app, permissions, expect);

// Create rows and assert the permissions relevant to your application session.
await policyApp.shutdown();
```

## Test sync and offline behavior

`startLocalJazzServer()` starts an isolated serving node. Open one client per test actor with the
returned app ID and URL. Call `disconnect()` to hold a client on its local snapshot, perform local
writes, then call `reconnect()` and wait for the desired edge or global durability tier.

```ts
import { createDb, generateAuthSecret } from "jazz-tools";
import { deploy, startLocalJazzServer } from "jazz-tools/testing";
import { app } from "../schema.js";
import permissions from "../permissions.js";

const server = await startLocalJazzServer({ inMemory: true });
await deploy({
  appId: server.appId,
  serverUrl: server.url,
  adminSecret: server.adminSecret,
  schema: app,
  permissions,
});

const alice = await createDb({
  appId: server.appId,
  serverUrl: server.url,
  secret: generateAuthSecret(),
  driver: { type: "memory" },
});

await alice.disconnect();
const pending = alice.insert(app.todos, { title: "Works offline" });
await pending.wait({ tier: "local" });
await alice.reconnect();
await pending.wait({ tier: "edge" });
await alice.shutdown();
await server.stop();
```

An exclusive transaction is the right test subject when a feature requires serializable read/write
behavior. Assert the accepted result and separately assert the rejection path for a concurrent
conflict. See [Writing Data](/docs/writing/writing-data#transactions).

## Validate the project contract

Run the schema and policy validator in CI:

```bash title="Terminal"
pnpm dlx jazz-tools@alpha validate
```
