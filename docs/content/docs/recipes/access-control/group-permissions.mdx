This recipe shows how to build a workspace where users have different levels of access depending on their role. The same pattern applies to any group-like concept&hairsp;—&hairsp;teams, projects, channels, organisations.

## Roles at a glance

| Role          | Read | Create | Edit own | Edit any | Manage members |
| ------------- | ---- | ------ | -------- | -------- | -------------- |
| `reader`      | ✓    |        |          |          |                |
| `contributor` | ✓    | ✓      | ✓        |          |                |
| `writer`      | ✓    | ✓      | ✓        | ✓        |                |
| `admin`       | ✓    | ✓      | ✓        | ✓        | ✓              |

## Schema

Three tables: the workspace itself, a members join table that records each user's role, and the documents that belong to the workspace.

```ts title="schema.ts"
import { schema as s } from "jazz-tools";

export const schema = s.defineSchema({
  workspaces: s.table(
    { name: s.string() },
    {
      members: s.reverse("workspaceMembers", "workspace"),
      documents: s.reverse("documents", "workspace"),
    },
  ),
  workspaceMembers: s.table(
    {
      workspaceId: s.uuid(),
      user_id: s.uuid(),
      role: s.enum("reader", "writer", "contributor", "admin"),
    },
    { workspace: s.rel("workspaces", "workspaceId") },
  ),
  documents: s.table(
    { title: s.string(), content: s.string(), workspaceId: s.uuid() },
    { workspace: s.rel("workspaces", "workspaceId") },
  ),
});
```

## Permissions

```ts title="schema.ts"
const { definePermissions, exists, session, anyOf, allOf } = schema;

type Role = "reader" | "writer" | "contributor" | "admin";

const isMember = (workspaceId: s.Uuid) =>
  exists.workspaceMembers({ workspaceId, user_id: session.user });
const hasRole = (workspaceId: s.Uuid, role: Role) =>
  exists.workspaceMembers({ workspaceId, user_id: session.user, role });
const isAdmin = (workspaceId: s.Uuid) => hasRole(workspaceId, "admin");

export const permissions = definePermissions({
  documents: {
    read: (doc) => isMember(doc.workspaceId),
    insert: (doc) =>
      anyOf(
        hasRole(doc.workspaceId, "writer"),
        hasRole(doc.workspaceId, "contributor"),
        hasRole(doc.workspaceId, "admin"),
      ),
    // Writers and admins can edit any document; contributors only their own.
    update: (doc) =>
      anyOf(
        hasRole(doc.workspaceId, "writer"),
        hasRole(doc.workspaceId, "admin"),
        allOf({ $createdBy: session.user }, hasRole(doc.workspaceId, "contributor")),
      ),
    // Writers and admins can delete any document; contributors only their own.
    delete: (doc) =>
      anyOf(
        hasRole(doc.workspaceId, "writer"),
        isAdmin(doc.workspaceId),
        allOf({ $createdBy: session.user }, hasRole(doc.workspaceId, "contributor")),
      ),
  },
  workspaces: {
    read: (ws) => isMember(ws.id),
    insert: true,
    update: (ws) => isAdmin(ws.id),
    delete: (ws) => isAdmin(ws.id),
  },
  workspaceMembers: {
    read: (m) => isMember(m.workspaceId),
    // Admins add members; a workspace's creator can add themselves as its first admin.
    insert: (m) =>
      anyOf(
        isAdmin(m.workspaceId),
        allOf(
          { user_id: session.user, role: "admin" },
          exists.workspaces({ id: m.workspaceId, $createdBy: session.user }),
        ),
      ),
    update: (m) => isAdmin(m.workspaceId),
    // Admins can remove any member; members can leave on their own.
    delete: (m) => anyOf(isAdmin(m.workspaceId), { user_id: session.user }),
  },
});
```

`isMember`, `hasRole` and `isAdmin` are plain TypeScript helpers: they take the workspace id to check
(`doc.workspaceId` on a document, `m.workspaceId` on a membership, `ws.id` on a workspace).
`npx jazz-tools generate` inlines them into `jazz.permissions.json`.

- **Contributor** edit access requires both `{ $createdBy: session.user }` (the row belongs to this author) and a matching contributor membership. Writers and admins bypass the creator check entirely.
- **Bootstrap insert**: the second branch of the `workspaceMembers` insert policy lets the workspace creator add themselves as the first admin&hairsp;—&hairsp;otherwise `isAdmin` would block everyone, since there are no members yet.
- **Leave on your own**: members can delete their own membership row regardless of role. Admins can remove anyone.

See [Declarative Permissions](/docs/schemas/policies) for more on `exists`, `anyOf`, `allOf`, and `$createdBy`.

### What a removed member still sees

- **Online** (thin client, or local-first while connected): the workspace's documents drop out of
  their live queries right away.
- **Offline local-first:** the rows already on their device stay readable, across reloads too,
  until they reconnect. Within about a second of reconnecting they are removed from the device.
  Writes they queued meanwhile are rejected and reverted.
- `clearOnSignOut` doesn't help here: a removed member isn't signed out.

Anything they read before removal they may have copied; removing access stops future reads, not
past ones.
