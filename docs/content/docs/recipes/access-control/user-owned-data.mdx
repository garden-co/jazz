This recipe covers building an app where users own their own data and no-one else can see it, covering schema, permissions, querying, and inserting.

## Schema

There's no need to add an explicit owner column&hairsp;—&hairsp;Jazz tracks who created each row automatically via `$createdBy`.

```json title="jazz.app.json"
{
  "$schema": "https://jazz.tools/schemas/jazz.app.v1.json",
  "tables": {
    "todos": {
      "columns": {
        "title": "string",
        "done": "boolean"
      }
    }
  }
}
```

See [Defining tables](/docs/schemas/defining-tables) for everything a table can declare.

## Permissions

Match `$createdBy` to `session.user` to validate whether the current user is the one who created the data. Because `$createdBy` is set automatically, we can allow every insert with `"true"`.

```json title="jazz.permissions.json"
{
  "$schema": "https://jazz.tools/schemas/jazz.permissions.v1.json",
  "tables": {
    "todos": {
      "read": "$createdBy.account = session.user",
      "insert": "true",
      "update": "$createdBy.account = session.user",
      "delete": "$createdBy.account = session.user"
    }
  }
}
```

These rules are enforced on the server. See [Declarative Permissions](/docs/schemas/policies) for combinators, `allowedTo`, and more complex options.

<Accordion title="Explicit owners for transferable ownership">

If ownership can be transferred after creation, use an explicit `owner_id` column instead of `$createdBy`.

```json title="jazz.app.json"
{
  "$schema": "https://jazz.tools/schemas/jazz.app.v1.json",
  "tables": {
    "todos": {
      "columns": {
        "title": "string",
        "done": "boolean",
        "owner_id": "uuid"
      }
    }
  }
}
```

```json title="jazz.permissions.json"
{
  "$schema": "https://jazz.tools/schemas/jazz.permissions.v1.json",
  "tables": {
    "todos": {
      "read": "owner_id = session.user",
      "insert": "true",
      "update": { "old": "owner_id = session.user" },
      "delete": "owner_id = session.user"
    }
  }
}
```

An update policy with only `old` checks the row before the update, so the current owner can rewrite `owner_id` to transfer the row. A plain string would also enforce the condition on the post-update row and block transfers. See [Declarative Permissions](/docs/schemas/policies) for `old`/`new` semantics.

`"insert": "true"` lets any user insert a row with any `owner_id`, including someone else's. That's the right default if you want users to be able to assign rows to others on creation; otherwise, narrow it to `"owner_id = session.user"` so clients can only create rows they own.

</Accordion>
