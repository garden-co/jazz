title: Sharing and Keys
description: "Add and remove the members of an encrypted space, and change its key."

---

A space is a row of the table your schema names as a `space`, such as a project. Its members
share its key. An account that can read and update the space row can add and remove members, so
the space row's update rule decides who manages them. Any member can remove themselves.

## Add members

When a signed-in client inserts a space row, Jazz adds the creator as a member in the same
transaction. Use `members.add` for everyone else.

```ts
const project = await db
  .insert(app.projects, { name: "Plans", ownerId: accountId })
  .wait({ tier: "global" });
await db.encryption.members.add(app.projects, project.id, otherAccountId).wait({ tier: "global" });
const members = await db.encryption.members.list(app.projects, project.id);
await db.encryption.members.remove(app.projects, project.id, otherAccountId);
```

In Rust, pass the generated space row type:

```rust
use jazz_app::{DurabilityTier, NewProject, Project};

let durable = jazz.durable(DurabilityTier::GlobalServer);
let project = durable.insert(NewProject::new("Plans", owner_id)).await?;
durable.add_member::<Project>(project.id, other_account).await?;
let members = jazz.list_members::<Project>(project.id).await?;
let removed = jazz.remove_member::<Project>(project.id, other_account).await?;
```

Swift and Kotlin have `addMember`, `listMembers` and `removeMember` on their `encryption` handle.
Go has `AddMember`, `ListMembers` and `RemoveMember` on `db.Encryption()`. They take the space
table's name and the row ID.

Jazz adds the creator only in these cases:

- The space is created with `insert`. After an `upsert`, add the creator yourself.
- The client is a signed-in device. A backend that creates a space for a user must add that user.
- Automatic membership is on. To turn it off, pass `{ addCreatorAsMember: false }` as the third
  argument of `db.insert`, or set it in the client's `encryption` options.

Adding the creator a second time fails with an "already a member" error.

To add a member together with other writes, use `tx.encryption.members.add`:

```ts
const written = await db.transaction((tx) => {
  tx.encryption.members.add(app.projects, project.id, otherAccountId);
});
await written.wait({ tier: "global" });
```

Members are rows of the `__e2ee_members` table. To query or write it yourself,
`db.encryption.members.where(space)` returns a filter for a space's member rows and
`db.encryption.members.row(space, accountId)` returns the values to insert. Here `space` is
`{ table: "projects", id: project.id }`.

On a device that has never synced, these calls can fail with `not-observed`. Try again after the
first sync.

## When members get the key

The first encrypted write to a space creates its key. A new member's devices get the key from a
device that already holds it, so one of those has to be online. Until the key arrives, the new
member's reads [leave the encrypted rows out](/docs/e2ee/getting-started#rows-this-device-cannot-read).

Jazz delivers keys when the app starts, when it reconnects, and while it has a subscription on
the space. To deliver straight away:

```ts
const { delivered } = await db.encryption.keys.deliver();
```

## Remove a member

`members.remove` returns the number of member rows it deleted. `0` means the caller could see no
member row for that account.

After a removal, the space needs a new key. Jazz makes one before the next encrypted write from
a member who can update the space row. To change the key immediately, call
`db.encryption.keys.rotate(space)`. If you remove several members, rotate once at the end.

`rotate` returns the number of members who got the new key in the same transaction, up to 100.
Jazz delivers it to the rest in the background. It can fail with these codes:

- `rotation-needs-key`: this device doesn't hold the current key yet. Try again once it does.
- `not-a-member`: this account isn't a member of the space.
- `no-account`: this device is waiting for approval.

A removed member keeps everything they could already read. They get no rows and no keys from
then on.

To delete your own rows in the same transaction as the membership, use
`db.serializableTransaction`. Read the member rows with the filter from
`members.where(space, accountId)`, delete them with your rows, and wait for the result before you
rotate.

If no online device holds the current key, a device that holds an earlier key can call
`db.encryption.keys.recoverRotation(space)`. Ask the user to confirm first. Rows written under a
key that no member's device still holds stay unreadable. See
[rotation and removal](https://github.com/garden-co/jazz/blob/main/crates/jazz/SPEC/E2EE_PROTOCOL.md#35-rotation-and-removal)
in the spec.

## Watch for failures

If Jazz can't change the key before a write, the write still goes ahead under the old key, which
the removed member may hold. Listen for this with `onReport`:

```ts
db.encryption.onReport((report) => {
  if (report.type === "rotation-check-failed")
    console.warn("rotation check failed", report.space, report.reason);
  if (report.type === "rotation-failed")
    console.warn("key not rotated", report.space, report.reason);
  if (report.type === "delivery-failed")
    console.warn("key delivery failed", report.space, report.reason);
});
```

- `rotation-check-failed`: Jazz couldn't check whether the space needs a new key.
- `rotation-failed`: the key wasn't changed before a write. The next write tries again. After a
  permission refusal, this client stops trying for the session.
- `delivery-failed`: Jazz couldn't deliver keys to the space's members. It tries again later.

## On the backend

The database from `createJazz` can add, list and remove members through `db.encryption.members`.
It holds no keys, so it can't deliver or rotate them. Use a device client for that.
