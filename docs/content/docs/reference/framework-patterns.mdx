Jazz provides framework-specific bindings for React/Expo, Vue, Svelte, and Solid. This page
is a side-by-side reference&hairsp;—&hairsp;see [Reading Data](/docs/reading/queries),
[Writing Data](/docs/writing/writing-data), and [How Auth Works](/docs/setup/auth/backend#the-session) for
full details.

## API equivalents

| Concept            | React / Expo               | Vue                        | Svelte                            | Solid                       |
| ------------------ | -------------------------- | -------------------------- | --------------------------------- | --------------------------- |
| Provider           | `<JazzProvider>`           | `<JazzProvider>`           | `<JazzProvider>`                  | `<JazzProvider>`            |
| Jazz session       | `useJazzSession()`         | `useJazzSession()`         | `getJazzSession()`                | `useJazzSession()`          |
| Query subscription | `useAll(query)`            | `useAll(query)`            | `new QuerySubscription(query)`    | `useAll(() => ({ query }))` |
| Single-row query   | `useOne(query)`            | `useOne(query)`            | `new QuerySubscriptionOne(query)` | `useOne(() => ({ query }))` |
| DB access          | `useAll(query).db`         | `useAll(query).db`         | `subscription.db`                 | `useAll(...).db`            |
| Write-only DB      | `useDb()`                  | `useDb()`                  | `getDb()`                         | `useDb()`                   |
| Permission session | `useSession()`             | `useSession()`             | `getSession().current`            | `useSession()`              |
| Client without UI  | `createJazzClient(config)` | `createJazzClient(config)` | `createJazzClient(config)`        | `createJazzClient(config)`  |

## Provider setup

Wrap your app in `<JazzProvider config={…}>`. `config` takes the same options as
`createJazzClient` (`serverUrl`, `client`, `initial` and the rest; see
[Thin Client](/docs/setup/web-client/thin-client)). The provider shows its `signedOut` view while no
one is signed in, `loading` while Jazz starts or switches users, and `error` when there is no usable
client. Once its session is closed (`session.close()`), it shows its `closed` view: nothing unless
you give one. A closed session never starts again: give the provider a new session, or a new `key`
for its `config`. `useJazzSession()` (Svelte: `getJazzSession()`) reads the session anywhere below, including
in those views.

  <Tab value="React">
    ```tsx title="App.tsx"
    import { JazzProvider } from "jazz-tools/react";

    export function Root() {
      return (
        <JazzProvider
          config={{ serverUrl: "/jazz", client: () => import("jazz-tools/local-first") }}
          signedOut={<SignIn />}
          loading={<p>Loading…</p>}
          error={(state) => <button onClick={state.retry}>{state.error?.message}: retry</button>}
        >
          <App />
        </JazzProvider>
      );
    }
    ```

  </Tab>
  <Tab value="Vue">
    ```vue title="App.vue"
    <script setup lang="ts">
    import { JazzProvider, type JazzClientConfig } from "jazz-tools/vue";
    const config: JazzClientConfig = {
      serverUrl: "/jazz",
      client: () => import("jazz-tools/local-first"),
    };
    </script>

    <template>
      <JazzProvider :config="config">
        <TodoApp />
        <template #signedOut><SignIn /></template>
        <template #loading><p>Loading…</p></template>
        <template #error="{ error, retry }">
          <button @click="retry">{{ error.message }}: retry</button>
        </template>
      </JazzProvider>
    </template>
    ```

  </Tab>
  <Tab value="Svelte">
    ```svelte title="App.svelte"
    <script lang="ts">
      import { JazzProvider } from "jazz-tools/svelte";
    </script>

    <JazzProvider config={{ serverUrl: "/jazz", client: () => import("jazz-tools/local-first") }}>
      <TodoApp />
      {#snippet signedOut()}<SignIn />{/snippet}
      {#snippet loading()}<p>Loading…</p>{/snippet}
      {#snippet error(error, retry)}
        <button onclick={retry}>{error.message}: retry</button>
      {/snippet}
    </JazzProvider>
    ```

    Call `getDb()`, `getJazzSession()` and the other `get…` helpers during component setup (the
    top level of a component's `<script>`), not later in an event handler: they read Svelte
    context. Stores and utility modules can't, so pass them the db from there.

    In SvelteKit, render the provider only in the browser (`{#if browser}` from `$app/environment`)
    and load server-rendered data in `+page.server.ts` with
    [`jazz.forReqUser`](/docs/setup/deployment/own-server#user-scoped-use). For production builds,
    add `ssr: { external: ["jazz-napi"] }` to `vite.config.ts` so Vite doesn't bundle Jazz's native
    module. Behind a proxy that terminates TLS, set `adapter-node`'s `PROTOCOL_HEADER` (for example
    `x-forwarded-proto`), or Jazz sees `http://` and refuses sign-in as an origin it doesn't allow.

  </Tab>
  <Tab value="Solid">
    ```tsx title="App.tsx"
    import { JazzProvider } from "jazz-tools/solid";

    export function Root() {
      return (
        <JazzProvider
          config={{ serverUrl: "/jazz", client: () => import("jazz-tools/local-first") }}
          signedOut={<SignIn />}
          loading={<p>Loading…</p>}
          error={(error, retry) => <button onClick={retry}>{error.message}: retry</button>}
        >
          <App />
        </JazzProvider>
      );
    }
    ```

  </Tab>
</Tabs>

Leave out `client` for a thin client. The provider creates its session when it mounts and closes it
when it unmounts; use a `key` to replace it with a new config. To show a session you opened yourself
with `createJazzClient`, pass `session={session}` instead of `config`; the provider then leaves
closing it to you.

## Session/user identity

Two things are called a session, and they answer different questions:

- **Who is signed in on this device:** the Jazz session, from `useJazzSession()` (Svelte:
  `getJazzSession()`). Its `user` is `{ accountId, kind, identity, claims }`, with `kind`
  `"device"` for a device account (a guest) and `"backend"` for a user your backend signed in, or
  `null`. It also carries the operations: `refresh()`, `signOut()`, `createDeviceAccount()` and the
  rest.
- **What your permissions see:** `useSession()` (Svelte: `getSession()`), the read-only session a
  query or write runs with, whose `user` is the account ID your policies compare.

See [How Auth Works](/docs/setup/auth/backend#the-session) for details on authentication modes and identity linking.
