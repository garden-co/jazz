## For developers

Jazz is your whole data layer: database, sync, streams and files, running inside the backend you
already have.

Without it, that layer is usually assembled by hand: a traditional database for tables, a blob
provider for files, a stream or pub/sub service for chat, presence and agent output, and a sync
layer so screens update live and keep working on a flaky connection. Each piece has its own client,
its own idea of who the user is and its own permission rules, and your team writes and maintains
the glue that keeps them consistent.

With Jazz:

- **Your app and its data live together.** Jazz runs inside your backend, so there's one less
  vendor and one less service to run. Tables, relations and a typed client work the same in backend
  and frontend. Jazz plugs into whatever auth your backend uses, and clients sync with your backend
  over a same-origin endpoint (`/jazz` by default) using your app's existing session.
- **Your API layer mostly disappears.** Permissions are declarative, so browsers and API routes can
  run Jazz queries and transactions directly, and Jazz checks each one for the user making it.
  Backend code can act with full trusted access or as a specific user, so you only write endpoints
  for logic a policy can't express.
- **Sync built in.** Subscribe to any query and your UI stays current on its own: a feed, a
  dashboard or a shared list updates the moment someone adds, edits or removes a row. When a screen
  needs instant writes or offline support, switch that client to local-first, with the same schema,
  queries and policies.
- **Streams and files in the same model.** Files, streams and mergeable text live in Jazz too, so
  they sync and follow your permissions like every other value. Edit metadata
  (`$createdBy`, `$updatedAt`, …), history, drafts and branches come with every row.
- **One set of permissions.** Policies live next to your schema in TypeScript and apply the same way
  to backend code, thin clients, local-first clients, files and streams. They're verbose, but agents
  are good at writing and checking them.

## For engineering leaders

- **Less code to maintain:** no glue code for data access, sync or permissions.
- **Fewer moving parts:** live and collaborative features natively in Jazz, without a separate
  stack.
- **Keep your existing auth:** your backend passes each user's identity to Jazz, including roles and
  claims from your identity provider, and policies check them directly.
- **Choose where it runs:** run Jazz on your own infrastructure, bring your own cloud, or use Jazz
  Cloud.
- **Licensing:** MIT for unsharded Jazz; unlock sharding with an enterprise license.
