## For developers

Think of Jazz as a modern Supabase that you host yourself, right next to your app. You get a relational database, auth integration, permissions and a typed client for backend and frontend, with no API layer of your own to write and maintain. Then it goes further:

- **Yours to run.** Deploy it on Vercel, Cloudflare or your own servers instead of a separate hosted service. It scales from zero for small apps up to many shards for big ones. Unsharded Jazz is MIT and free.
- **Live queries, not change feeds.** Every query can be a subscription. The server keeps results up to date as rows change, including rows that start or stop matching.
- **Permissions as code.** Policies live next to your schema in TypeScript and apply the same way to backend, thin-client and local-first reads and writes. They're verbose, but agents are good at writing and checking them.
- **Built-in collaboration.** Edit metadata (`$createdBy`, `$updatedAt`, …), history, drafts and branches, mergeable text, and files and streams, without bolting on extra services.
- **Local-first when it pays off.** Start with server-first reads and writes. Switch a client to local-first for instant UI and offline support, with the same schema, queries and policies.

## For decision-makers

- Custom code as a liability: less backend code to own
- Fewer systems and moving parts
- Runs in your own cloud: Vercel, Cloudflare, AWS, bare metal
- What you operate yourself on each platform, plus a cost calculator
- Licensing: MIT for unsharded Jazz, a license for sharded Jazz
