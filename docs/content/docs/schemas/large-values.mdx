<Callout type="warn" title="Draft API proposal">
  The TypeScript and Rust calls on this page describe the API being implemented on this branch, not
  an API available in a released Jazz version.
</Callout>

Large values are ordinary `string`, `bytes`, and `json` columns. They are not a separate content
type or sync system. Small values are stored inline; once a value grows, Jazz transparently changes
its physical representation while preserving the owning row's permissions, transactions, history,
subscriptions, and conflicts.

## Define the schema

The schema describes the logical value, not its expected size or access pattern:

```ts
const schema = {
  documents: s.table({
    body: s.string(),
    recording: s.bytes(),
    attachment: s.bytes(),
    metadata: s.json(),
  }),
};
```

Normal queries return a complete `string`, `Uint8Array`, or parsed JSON value. Normal mutations
accept the same types. This keeps the common case indistinguishable from a small column.

## Partial reads

A partial query still returns a plain primitive, not a content handle or slice object.

### Text

TypeScript text positions use UTF-16 code units, matching `String.prototype.slice()`, `NSString`,
and common editor APIs:

```ts
const slice = { from: 1_000, length: 2_000 };
const excerpt = await db.one(
  app.documents.where({ id: documentId }).select({
    $version: true,
    body: { slice },
  }),
);

excerpt?.body; // plain string containing UTF-16 units 1,000..<3,000
```

Rust exposes both coordinate systems explicitly. UTF-8 byte positions are available for all large
values; text additionally supports UTF-16 positions for JavaScript and Apple interoperability:

```rust
let bytes = columns::body.slice_utf8(1_000..3_000);
let js_units = columns::body.slice_utf16(1_000..3_000);
```

UTF-8 text positions must lie on code-point boundaries. UTF-16 positions must not split a surrogate
pair. Invalid positions are rejected rather than rounded.

### Byte streams and files

Byte slices use byte offsets in every binding and return a detached `Uint8Array` in TypeScript:

```ts
const result = await db.one(
  app.documents.where({ id: documentId }).select({
    $version: true,
    recording: { slice: { from: resumeAt, length: 64 * 1024 } },
    attachment: { slice: { from: 0, length: headerLength } },
  }),
);
```

Applications can build streaming helpers from successive bounded queries. A native streaming API
is deliberately deferred from this first client surface.

### JSON

`pointer` returns the detached native JSON value at an RFC 6901 JSON pointer:

```ts
const result = await db.one(
  app.documents.where({ id: documentId }).select({
    metadata: { pointer: "/chapters/3/title" },
  }),
);
```

## Editing without materializing

Edits repeat the slice used for the read and express the edit position relative to it. Keeping
those coordinates together is the caller's responsibility; no provenance is hidden inside the
returned primitive.

Select the row's `$version` with the slice and pass it as `ifVersion` when updating. This is a
general row-level compare-and-swap condition. The mutation fails if any part of the row changed
after the read.

### Edit text

In TypeScript, every text position is a UTF-16 code-unit count:

```ts
const slice = { from: 1_000, length: 500 };
const document = await db.one(
  app.documents.where({ id: documentId }).select({
    $version: true,
    body: { slice },
  }),
);

db.update(
  app.documents,
  documentId,
  {
    body: {
      splice: {
        slice,
        at: 120,
        delete: 11,
        insert: "large values",
      },
    },
  },
  { ifVersion: document!.$version },
);
```

Use `delete: 0` to insert or `insert: ""` to delete. Passing a plain string replaces the whole
value. Rust offers corresponding `splice_utf8(...)` and `splice_utf16(...)` operations.

### Append to a byte stream

```ts
db.update(
  app.documents,
  documentId,
  { recording: { append: nextAudioChunk } },
  { ifVersion: document.$version },
);
```

### Edit a file

For bytes, every position is a byte offset:

```ts
db.update(
  app.documents,
  documentId,
  {
    attachment: {
      splice: {
        slice: { from: 0, length: headerAndPreviewLength },
        at: headerLength,
        delete: oldPreviewLength,
        insert: newPreviewBytes,
      },
    },
  },
  { ifVersion: document.$version },
);
```

The same operation covers insertion, deletion, and replacement. Passing a plain `Uint8Array`
replaces the whole file.

### Replace JSON

JSON keeps one write shape: pass the desired native JSON value. Jazz derives a compact byte edit
without exposing byte offsets in the JSON API. JSON remains one logical value; merge strategies may
parse the base and both candidates to obtain a semantic, side-attributed diff.

## What happens underneath

Small values live inline. Large values use an immutable, content-defined chunk tree plus a short
tail of recent byte edits. Every tree records aggregate UTF-8 byte lengths. Text trees additionally
record aggregate UTF-16 lengths. Resolving either coordinate system traverses those metrics in
logarithmic time and scans only the target chunk.

An edit tail records its changes in both metrics. When the tail reaches a built-in bound, Jazz
consolidates it into a new immutable tree and updates metrics only along rewritten paths. Range
reads visit only relevant nodes and chunks, keeping memory proportional to the data being accessed.

The tree and edit tail form one atomic cell in the owning row. Readers never combine the tree from
one row version with edits from another, and all writes continue through normal Jazz row
permissions, sync, history, transactions, and conflict handling.
