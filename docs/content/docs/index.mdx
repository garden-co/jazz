Every Jazz app is defined first by its database schema and permission policies. They're verbose, but agents are good at writing and checking them.

```ts title="schema.ts"
import { schema as s } from "jazz-tools";
import { migrations } from "./migrations";

export const app = s.defineApp(
  { todos: s.table({ title: s.string(), done: s.boolean() }, {}) },
  { migrations },
);

// Each user sees and edits only the todos they created
export const permissions = s.definePermissions(app, ({ policy, session }) => {
  const isCreator = { $createdBy: session.user };
  policy.todos.allowRead.where(isCreator);
  policy.todos.allowInsert.where(isCreator);
  policy.todos.allowUpdate.where(isCreator);
  policy.todos.allowDelete.where(isCreator);
});
```

Jazz runs inside your backend: no separate database server and no deploy step. The schema and permissions your code imports are the ones it enforces.

```ts title="server.ts"
import { Hono } from "hono";
import { createJazz, sqlite } from "jazz-tools/backend";
import { app, permissions } from "./schema";

const jazz = await createJazz({
  app,
  permissions,
  store: sqlite({ path: "./data/jazz" }),
  authenticate: async (request) => getSignedInUser(request), // your own auth: { userId } or null
});

new Hono()
  // Runs with backend authority and sees every todo (check admin access in your app first)
  .get("/admin/todos", async (c) => {
    return c.json(await jazz.db.all(app.todos));
  })
  // Runs as the signed-in user: the query only returns their own todos
  .get("/todos", async (c) => {
    const db = await jazz.forRequest(c.req.raw);
    return c.json(await db.all(app.todos.where({ done: false })));
  })
  // Sync for browsers, on your own origin
  .all("/jazz/*", (c) => jazz.fetch(c.req.raw));
```

You can also query and write to the database right from your frontend. It is protected by the same auth as your backend, and the same permission policies apply. Pick a thin client (about 86 kB gzipped) or a full local-first client (about 1 MB gzipped, mostly the WASM engine).

    // Signs in through your backend's /jazz route, with your app's own session cookie
    const db = await createClient();

    import { Effect, Stream } from "effect";
    import { Jazz } from "jazz-tools/effect";
    import { app } from "./schema";

    const program = Effect.gen(function* () {
      const jazz = yield* Jazz;

      // Live query as a Stream: a full snapshot on start and on every change
      yield* jazz
        .stream(app.todos.where({ done: false }))
        .pipe(Stream.runForEach((todos) => Effect.log(todos)));
    });

    // Same config as createClient(): signs in through /jazz with your session cookie
    program.pipe(Effect.provide(Jazz.layer()), Effect.runPromise);

## What people build with Jazz

<Callout type="info">
  Preview: rough sketches of each scenario; each will link to a short path through the docs.
</Callout>

- **A backend with live data.** Your API or server components read and write through Jazz instead of an ORM, with permissions checked per user and live queries pushed to the browser. Path: [Quickstart](/docs/setup/run-locally) → [User-scoped backend](/docs/setup/backend/user-scoped) → [Policies](/docs/schemas/policies) → [Thin client](/docs/setup/web-client/thin-client).
- **A collaborative app.** Shared lists, boards or documents that several people edit at once, with mergeable text and edit history. Path: [Mergeable text](/docs/writing/text) → [Shared access](/docs/recipes/access-control/shared-access) → [Edit metadata](/docs/reading/metadata).
- **An app that works offline.** Field tools, note-taking or mobile apps that keep working without a connection. Path: start thin, then [go local-first](/docs/recipes/local-first) on the screens that need it, or use the [React Native client](/docs/setup/react-native).
- **Agents and automations.** Background jobs and AI agents that read and write the same data as your users, attributed and permission-checked. Path: [Trusted backend](/docs/setup/backend/trusted) → [Sessions](/docs/setup/auth/sessions) → [CLI & MCP](/docs/tooling/cli-and-mcp).
- **Drafts and review flows.** Edit a copy, compare it with the original, merge it back. Path: [Drafts & branches](/docs/recipes/drafts-and-branches).
