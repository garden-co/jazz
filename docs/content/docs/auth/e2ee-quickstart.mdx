Build a React chat with two tables: one for chats and one for encrypted messages.
Jazz manages the encryption keys and membership tables. Only the chat owner can
share it; members can read messages and write their own.

This guide uses React, TypeScript and a local Jazz server. E2EE is experimental;
see the [E2EE guide](/docs/auth/end-to-end-encryption) for its limits, recovery and
offline behaviour. For a fuller UI with image uploads, see the
[encrypted chat example](https://github.com/garden-co/jazz/tree/main/examples/e2ee-chat).

## 1. Create a React app

```sh
pnpm create vite encrypted-chat --template react-ts
cd encrypted-chat
pnpm install
pnpm add jazz-tools@alpha
```

Keep Vite's React plugin and add the Jazz plugin. During development Jazz starts
a local server, deploys your schema and permissions, and supplies the app ID and
server URL to the browser.

## 2. Declare the encrypted messages

Create `schema.ts` at the project root. Each chat is an encryption space;
`chatId` connects its messages to that space. The `owner` relationship lets
permissions verify who may create and administer it.

<include cwd lang="ts" meta='title="schema.ts"'>
  ../examples/e2ee-chat/quickstart/schema.ts
</include>

Message text is encrypted. Chat IDs, owner IDs, timestamps and sharing metadata
remain visible. This example lets signed-in accounts read chat metadata; message
access requires membership.

## 3. Define access and sharing

Create `permissions.ts` beside `schema.ts`. `fromEncryptionSpace()` gives members
access to messages. The `space` rules give the owner permission to create the
space and change its membership.

<include cwd lang="ts" meta='title="permissions.ts"'>
  ../examples/e2ee-chat/quickstart/permissions.ts
</include>

Keep `existsIncludingCreated` here: creating a chat also creates its initial
creator membership in the same transaction. Later administration checks use
accepted ownership. You do not need a separate application membership table.

## 4. Set up the React provider

Replace `src/main.tsx` with the following. `JazzProvider` restores the browser's
selected account, creates a local-first account on the first visit, and opens
the database with encryption enabled. It also handles loading, setup errors and
cleanup when unmounted.

<include cwd lang="tsx" meta='title="src/main.tsx"'>
  ../examples/e2ee-chat/quickstart/src/main.tsx
</include>

Keep the permissions import before the provider mounts, using the same `app`
instance. It registers the selected membership behaviour with the SDK; the
server enforces the deployed policies.

Browser account selection and encryption keys persist automatically in separate
stores. Use localhost or HTTPS with IndexedDB available, and retain browser
storage to keep your keys.

## 5. Add the chat component

Replace `src/App.tsx` with this component. `useDb()` provides writes and sharing;
`useSession()` provides the account ID. `useAll()` subscribes to decrypted
messages and updates the list when either account sends a message. `useOne()`
reads the chat owner so the UI shows sharing controls to that account.

<include cwd lang="tsx" meta='title="src/App.tsx"'>
  ../examples/e2ee-chat/quickstart/src/App.tsx
</include>

The Global wait in `createChat()` includes initial space acceptance and the
creator's key handoff. It completes before the component enables message writes.
Sharing grants both key access and the membership used by
`fromEncryptionSpace()`; the server enforces that only the owner may share.

Writes wait for the server to make the first two-account test easy to follow.
Reads use the hooks' default local-first subscriptions. For local saving and
offline use, see the
[completion guidance](/docs/auth/end-to-end-encryption#start-automatically-including-offline).

## Try it with two accounts

Run `pnpm dev` and open the URL Vite prints in two independent browser profiles,
or a normal and private window. Two tabs in the same profile share an account.

1. In the first profile, click **New chat** and send a message.
2. Copy the second profile's **account ID** into the first profile's
   **Recipient account ID** field, then click **Share chat**.
3. Once the app confirms sharing, copy the **Chat link** into the second profile.
   The message appears automatically. Send a reply to see it arrive in the first
   profile.

The recipient must have opened the app and completed account setup. If sharing
fails because their keys are not ready, let setup finish and explicitly retry
**Share chat** for the same chat and account. A chat link alone grants no access.

Reload either profile to check that its account, keys and messages persist.
