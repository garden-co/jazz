The account manager owns selection and credentials. A context owns queries, writes, and its runtime. Changing account selection does not change the identity of an existing context.

## Starting a context

```ts
import { createAccountManager, createJazzClient } from "jazz-tools/client";

const config = { appId: "my-app", serverUrl: "https://core.example" };
const accounts = await createAccountManager(config);
const account = accounts.getLoggedIn() ?? accounts.createLocalFirst();
let client: Awaited<ReturnType<typeof createJazzClient>> | undefined = await createJazzClient({
  ...config,
  account,
});
```

Browser managers retain local-first signing roots and selected-root metadata in browser storage. They never persist external provider JWTs. Other hosts supply an atomic `AccountStore`. Each server-rendering request must own its own manager rather than sharing credentials in a module singleton.

The account's registry authority is independent of active transport. Omit `serverUrl` from context creation to stay local-only. When supplied, it must match the handle's configured authority.

## Linking after graceful shutdown

Stop submitting application work and release any other holders of the shared client. The handoff must have exclusive ownership of its context. Wait for ordinary graceful shutdown, then link:

```ts
async function linkProvider(getToken: () => Promise<string>) {
  // If the sync barrier fails, the existing context remains usable.
  await client?.shutdown({ waitForSync: true });
  client = undefined;
  try {
    await accounts.linkJWT({ getToken });
  } finally {
    // Linking failure preserves selection, but concurrent logout clears it.
    const selected = accounts.getLoggedIn();
    if (selected) client = await createJazzClient({ ...config, account: selected });
    // Otherwise the app renders its signed-out state.
  }
}
```

The account manager does not track contexts or flush writes itself. `waitForSync` is a general shutdown option. A teardown failure after the sync barrier does not promise a usable old context. Ordinary shutdown without it remains usable offline and preserves local durability; it does not promise that remote synchronization finished.

Linked identities share the same account's durable storage root. Different acting identities cannot own that root concurrently: the old context closes before the new one opens. Earlier rows retain their original issuer and subject, while account ownership remains unchanged.

To log into a different account, use the same close / account operation / new context sequence with `loginJWT`. Register a new account explicitly with `registerJWT`.

## Logout

Close the context before clearing selection:

```ts
await client?.shutdown({ waitForSync: true });
accounts.logout();
await signOutFromYourProvider();
```

Logout invalidates all handles issued by that manager and fences pending operations so a late response cannot log the user back in. If a remote link completed just before cancellation, a later explicit login can discover the assignment.

Local-first signing roots remain retained for recovery. Logout does not erase the account's local database or revoke an identity at the core. Your provider owns its own cookies and login session.

## Recovery phrases and passkeys

Export a local-first root explicitly for backup:

```ts
import { exportLocalFirstSecret } from "jazz-tools";
import { RecoveryPhrase } from "jazz-tools/passphrase";

const secret = exportLocalFirstSecret(accounts.getLoggedIn()!);
const phrase = RecoveryPhrase.fromSecret(secret);
```

Use the same secret with `BrowserPasskeyBackup` from `jazz-tools/passkey-backup` for a passkey backup. Treat a recovery phrase as a credential: possessing it allows acting as that local-first identity.

Restore outside a context:

```ts
const secret = RecoveryPhrase.toSecret(recoveredPhrase);
await client?.shutdown();
const restored = accounts.restoreLocalFirst(secret);
client = await createJazzClient({ ...config, account: restored });
```

Export requires a live local-first handle. External and logged-out handles cannot export a signing root. Secrets never appear in account-state snapshots.

## Framework state

React and Vue provide `useAccountState(accounts)`, Solid provides `createAccountState(accounts)`, and Svelte provides `accountState(accounts)`. Each observes the same `{ account, pending, error }` snapshot.

A pending login or link preserves the current handle. Show errors beside the account controls; do not replace a working context merely because an account request started. The app owns the handoff shown above, and can render a loading state between the old context closing and the replacement opening.

## Storage reset

Account credentials and database contents are separate. `db.deleteClientStorage()` clears supported browser database storage without erasing the account's retained signing roots. Use it for development resets, not account registration or linking.
