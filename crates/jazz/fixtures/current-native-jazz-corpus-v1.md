# Current native Jazz corpus: V1 refresh

`current-native-jazz-*` is a positive corpus regenerated by the native producer.
It must reopen with current code. The separate `epoch-1-*` archives remain
unchanged as historical negative evidence and must still be rejected.
The previous DAG-layout current corpus is kept as `pre-linear-native-jazz.*`
negative evidence: `crates/jazz/tests/storage_format_refusal.rs` proves both
adapters refuse it with `UnsupportedStorageCodecs` and leave it unchanged.

Regenerate into a fresh output directory with:

```sh
JAZZ_NATIVE_CORPUS_ROCKS_ARCHIVE_OUT=/tmp/jazz-marker-free-fixtures/rocks.tar.gz \
JAZZ_NATIVE_CORPUS_SQLITE_OUT=/tmp/jazz-marker-free-fixtures/jazz.sqlite \
JAZZ_NATIVE_CORPUS_PACK_OUT=/tmp/jazz-marker-free-fixtures/corpus.pack \
dev/t settlement_baseline_native_jazz_corpus_reopens_and_accepts_mixed_writes -- --nocapture
```

Base64-encode the pack and RocksDB archive. Compress the SQLite image with gzip
using `mtime=0`, then base64-encode it. Update the artifact digests in
`native_storage_corpus.rs` and run
`committed_native_jazz_physical_corpus_reopens_and_accepts_current_writes`.

The logical pack has 33 entries in the linear row-history layout
(`jazz.history-version-current.v4`, `groove.durable-index.v2`). The DAG-era
families `jazz_deletion_history`, `jazz_global_changes`, `jazz_merge_heads`,
`jazz_pending_edges` and the `*_register*` families no longer exist; per-tx
touched rows live in `jazz_tx_touched_rows`.
History records carry an empty `counter_signs` byte string after
`authored_columns` (SPEC 4 §4.3), so the history bytes and every digest below
were regenerated when that field was added.
History records are keyed `(branch_key, row_uuid, seq, tx_time, tx_node_id)`
and end with the ancestor-merge fields `seq`, `base_seq`, `base_pending` and
`lost_cells` (SPEC 4 §4.6); no record carries column stamps any more. The
corpus was regenerated again for that layout.

The one `jazz_subscription_watermarks_v1` record names a catch-up revision that
is a fresh random id per catch-up. The receipt pins its key, record version and
settled seq, and replaces only that 16-byte nonce with a fixed placeholder, so
both adapters and repeated producer runs agree.

Row metadata and transaction provenance use the non-null native author record
`{ account: UUID, identity: { issuer: String, subject: String } }`. SYSTEM authors
use the reserved nil account UUID, `urn:jazz:system` issuer, and originating node
UUID as subject. This stored attribution does not grant the internal SYSTEM
permission capability. The author interner remains memory-only.

The RocksDB archive retains internal column family
`__groove_storage_internal_v1` and profile marker `raw-v1`. ResultKey V1 has a
separate golden fixture; this corpus contains no ResultKey occurrence payload.
